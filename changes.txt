Current Implementation

The current CrimeLens system allows any user to submit a crime report without authentication. During report submission, users are required to manually provide their personal information, including full name, CNIC number, contact number, and other relevant details along with the crime report data. These details are stored in the CrimeReportSubmitters table and are collected every time a report is submitted. The system already includes a separate authentication mechanism for administrative users and police agents, where credentials are stored in the User table and access permissions are managed through the Role table. Currently, only the Admin and Police roles exist, and citizen users do not have dedicated accounts, authentication, profile management, or report ownership capabilities.

Proposed Enhancement

The objective is to introduce a dedicated citizen authentication system using Supabase Auth with support for Email/Password registration, Email Verification, and Google OAuth login. Citizens will be required to authenticate before submitting any crime reports. Instead of collecting personal information during each report submission, a dedicated user profile will be maintained and linked to the authenticated account. After registration or first-time OAuth login, users will be required to complete mandatory profile information such as CNIC, address, and contact number (which are not taken at the time of sign up. At sign up , only name and email and password would be required) before gaining access to report submission features. Crime reports will then be associated directly with the authenticated user through a unique user identifier, eliminating duplicate collection of personal information and improving data consistency. Additionally, a citizen dashboard will be introduced to allow users to manage their profiles and view the status and history of their submitted reports. This enhancement aims to improve system security, accountability, user experience, and overall project quality while demonstrating modern authentication and authorization practices suitable for a production-style application.

Phase 1 — Authentication Foundation
Configure citizen authentication using Supabase Auth.
Add user signup with email and password.
Add email verification requirement.
Add Google OAuth login.
Create authentication flows separate from the existing Admin/Police login system.
Define how citizen accounts relate to existing application users and roles.
Phase 2 — User Profile System
Refactor the CrimeReportSubmitters table into a complete citizen profile table.
Add fields required for authenticated citizen reporting (CNIC, address, phone number, etc.).
Link profiles to authenticated Supabase users.
Introduce profile completion status tracking.
Migrate or clean up existing submitter data if necessary.
Ensure every citizen account has a single associated profile.
Phase 3 — Profile Completion Enforcement
Implement profile management screens.
Require citizens to complete mandatory profile information after registration.
Prevent incomplete-profile users from accessing report submission.
Allow users to view and update their profile information.
Establish validation rules for profile completeness.
Phase 4 — Report Submission Refactor
Remove personal information fields from the crime report form.
Associate every report with the authenticated citizen account.
Automatically retrieve citizen details from the profile instead of report inputs.
Update backend APIs and database relationships to use authenticated user identities.
Ensure reports cannot be submitted anonymously.
Preserve report ownership and traceability.
Phase 5 — User Dashboard & Access Control
Create a citizen dashboard experience.
Implement "My Reports" functionality.
Allow users to track the status of their submitted reports.
Restrict access so users can only view and manage their own reports.
Integrate citizen authentication with the existing Admin and Police workflows.
Verify end-to-end authorization rules across all user types.
